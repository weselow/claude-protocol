# 2026-11-24 — навык memory-sort: разбор памяти проекта в общую

Задача uyf.4 из эпика uyf (память). Разобрать, что из накопленной памяти
проекта нужно всем проектам, программа не может — решает модель. Поэтому это
навык, а не код: `templates/skills/memory-sort/SKILL.md`. Плагин грузит его
сам (`"skills": "./templates/skills"` → `/claude-protocol:memory-sort`),
установка через `npx` копирует через `copy_skills` — список навыков там уже
строится по каталогам, правки в `bootstrap.py` не понадобились.

Что делает навык: находит общую память по `claude-protocol.json`
(`shared_memory.choice` и `path` — то, что пишет `_save_shared_memory_state`),
память проекта — `.memory/` главного каталога (из рабочей копии — через
`git rev-parse --git-common-dir`), сортирует по проверке маршрута из блока
`templates/shared-memory/CLAUDE-block.md`, показывает нумерованный список,
секреты отдельно и без переноса, переносит только подтверждённое, убирает
повторы, коммитит и отправляет общую память.

Что проверять первым при поломке: тесты `TestMemorySortSkill` в
`tests/test_bootstrap.py`. Они падают, если поменялась формулировка вопроса
маршрута в блоке («will this help in another project?») — тогда навык надо
поправить под неё, а не держать вторую проверку; и если переименовали файл
состояния или ключ `shared_memory`.

Осознанно не тронуто: русского варианта навыка нет — навыки в репозитории
только на английском, и плагин грузит один каталог. Поиск секретов — на
суждении модели, без отдельного сканера.

Круг ревью R1–R5. Файлы читаются порциями по ~30 (прочитал — разобрал —
спросил — перенёс — следующая), иначе память на сотни файлов заливает весь
разговор. Новый исход «правило»: как работать — это не память, предлагается
правка правила. Чтобы перенесённое из bd не возвращалось при обновлении,
перенос bd ведёт список `.memory/.bd-imported` (см. журнал project-memory);
`bd forget` по-прежнему не вызывается.
