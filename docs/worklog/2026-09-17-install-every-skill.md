# 2026-09-17 — установщик ставит все навыки

Плагин загружает каждый каталог в `templates/skills` (поле `skills` в
`.claude-plugin/plugin.json`), а `bootstrap.py` знал по имени только
`project-discovery` — и при копировании (`copy_skill`), и в списке того, что
отдаётся плагину (`plugin_provided_relpaths`). Второй навык дошёл бы только до
тех, кто ставит плагин, а `--project-only` оставил бы его копию в проекте.
Задача выделена из pw6 (новый навык ревью), чтобы тот навык сразу доходил и
до установки через `npx`.

## Что сделано

- Новая функция `shipped_skill_files()` в `bootstrap.py` обходит каждый
  каталог в `templates/skills` и отдаёт ключи манифеста вида
  `skills/<навык>/<файл>`, включая вложенные файлы. Отдельный файл в самой
  `templates/skills` навыком не считается: плагин грузит только каталоги.
- Скрытые файлы и каталоги (имя с точки: `.DS_Store`, `.git`) и `__pycache__`
  пропускаются на любой глубине. `.DS_Store` — двоичный файл, и чтение его как
  текста (`read_verbatim`) обрывало весь запуск ошибкой `UnicodeDecodeError`.
  Так было и раньше для `project-discovery`, но теперь это касалось бы любого
  каталога навыка. Найдено на ревью.
- `copy_skill` стала `copy_skills` и берёт список оттуда. Каждый файл
  по-прежнему идёт через `installer.install`: правленый файл — вопрос, свой
  файл человека рядом не трогается. Параметр `with_skill` стал `with_skills`.
- `plugin_provided_relpaths` берёт навыки из того же списка, так что установка
  и уборка при `--project-only` разойтись не могут.
- «hooks, agents and skill» во множественном числе — в выводе, справке
  `--project-only` и комментариях; в README — там, где речь о поведении
  установщика, плюс запись в «Unreleased» / «Не выпущено».

## Тесты

Шесть новых в `tests/test_bootstrap.py`, классы `TestEverySkillIsInstalled` и
`TestEverySkillIsHandedOver`. Тестовые данные — копия `templates` во временном
каталоге с добавленным навыком `other-skill` (с вложенным файлом) и отдельным
`README.md` рядом с каталогами. `bootstrap.TEMPLATES_DIR` подменён на эту
копию, `CLAUDE_CONFIG_DIR` — на пустой каталог, чтобы плагин, стоящий на
машине, не превратил обычный запуск в `--project-only`. Тест уборки
записывает второй навык в манифест вручную: иначе он проходил и до
исправления, потому что навык просто не ставился. Проверка «отдельный файл —
не навык» зелёная и до исправления — она сторожит границу, а не воспроизводит
ошибку; остальные пять на старом коде падают. Проверка скрытых файлов
подкладывает двоичные `.DS_Store`, файл в `__pycache__`, файл в скрытом
подкаталоге и целый скрытый каталог навыка.

## Что проверять первым, если сломается

- Навык или его файл не поставился через `npx` — `shipped_skill_files()` и
  `_in_a_skill()`: каталог ли это, есть ли в нём файлы, не начинается ли имя
  каталога или файла с точки.
- После `--project-only` навык остался в проекте — есть ли его файлы в
  `.claude/.manifest.json`. Уборка трогает только то, что там записано.
- В `tests/test_bootstrap.py` концы строк смешанные (часть файла LF), а
  инструмент правки переводит весь файл в CRLF. Вставлять в него байтами и
  сверять `git diff --stat` с числом добавленных строк.

## Что осознанно не тронуто

- Навык, убранный из `templates/skills` в следующем выпуске, из проектов не
  удаляется — отдельный вопрос, вне этой задачи.
- `.claude-plugin/marketplace.json` и `commands/init.md` называют
  `project-discovery` или «skill» в единственном числе. Это описание плагина,
  а не установщика; неверным оно станет с выходом второго навыка (pw6).
- Сам второй навык — в `templates/skills` ничего не добавлено.
- Запись о v3.8.0 в README («hooks, agents and skill») — история выпусков не
  переписывается.
