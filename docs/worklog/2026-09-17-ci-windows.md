# 2026-09-17 — тесты в CI на Windows и на каждую отправку в main

До этой правки тесты в GitHub Actions шли только в `release.yml`, только на
`ubuntu-latest` и только при отправке метки версии. Тесты, которые имеют смысл
лишь на Windows (обёртки `.cmd` через cmd.exe, путь Git Bash в отчёте), на
Linux пропускаются — значит, в CI не выполнялись никогда, хотя большинство
пользователей пакета сидит на Windows. Поломка становилась видна не раньше
выпуска.

## Что сделано

**`.github/workflows/test.yml`** — единственное описание прогона тестов:
матрица `ubuntu-latest` и `windows-latest`, Node 24, Python 3.12, `npm test` и
`pytest tests/test_bootstrap.py`. Запускается на отправку в `main`, на каждый
PR, вручную (`gh workflow run test.yml --ref <ветка> --repo
weselow/claude-protocol`) и из `release.yml` (`workflow_call`).
`fail-fast: false`: если упала одна система, вторая всё равно доходит до конца
— поломка только на одной системе и есть то, ради чего матрица заведена.

**`release.yml`** — задание `test` теперь просто вызывает `test.yml`. Имя
задания прежнее, поэтому `publish` (`needs: test`) не тронут ни строкой и
по-прежнему ждёт всю матрицу. Публикация осталась в `release.yml`: к имени
этого файла привязан доверенный издатель npm.

Почему вызов, а не копия матрицы в двух файлах: копии расходятся молча, а
смысл задачи в том, чтобы выпуск проверялся тем же прогоном, что и каждый PR.

**Концы строк.** В репозитории вперемешку CRLF и LF, `.gitattributes` нет. На
Windows git по умолчанию настроен с `core.autocrlf=true` и при выгрузке
превращает все 68 файлов с LF в CRLF. Проверено на локальном клоне с этой
настройкой: vitest проходит, а в pytest падают четыре теста
(`TestClaudeMdBlockIsRefreshed` — три, `TestClaudeMdAsksBeforeTouchingYourEdits`
— один). Поэтому первым шагом задания идёт
`git config --global core.autocrlf false`: тесты видят ровно те байты, что
лежат в репозитории, — как у разработчика и как в пакете npm, который
собирается на Linux. На Linux шаг ничего не меняет.

**Временный каталог на Windows.** Первый настоящий прогон упал на Windows в
одном тесте: `hook-utils.test.js` → «finds a repository whose path contains a
space». Машина GitHub задаёт TEMP в коротком виде 8.3
(`C:\Users\RUNNER~1\AppData\Local\Temp`), git возвращает длинный вид того же
каталога (`C:\Users\runneradmin\...`), а `fs.realpathSync` короткие имена не
раскрывает (`fs.realpathSync.native` раскрывает — проверено). Это свойство
машины CI, у разработчика TEMP длинный, поэтому исправлено в процессе: на
Windows TEMP и TMP указывают на `RUNNER_TEMP` задания.

**Подробный вывод vitest** (`npm test -- --reporter=verbose`): каждая
проверка на своей строке, в журнале Windows видно, что тесты только для
Windows выполнились (✓), а не пропущены (↓). Разделитель `--` доходит до
vitest и через `npm.ps1` в PowerShell — видно по тому же журналу.

**`.claude/rules/release-process.md`** — порядок выпуска: сначала отправить
коммит с версией и дождаться зелёного прогона Tests, потом метку; раздел о
тестах в CI.

## Как проверено

Путь выпуска проверен без метки: временный процесс на ветке вызывал
`test.yml` так же, как `release.yml`, с заглушкой вместо публикации. Первый
прогон — Windows упал на коротком TEMP, заглушка пропущена (зависимость от
всей матрицы работает). Второй, после исправления — всё зелёное: Ubuntu 257
пройдено и 5 пропущено (ровно пять тестов только для Windows), Windows 262 из
262, pytest 356 на обеих. Временный процесс удалён отдельным коммитом.

## Что проверять первым при поломке

- Windows упал, Linux зелёный, в тесте сравниваются пути — посмотреть, не
  вернулся ли короткий TEMP (шаг `Use a temp directory without 8.3 short
  names`) и нет ли `RUNNER~1` в тексте ошибки.
- Упали тесты с отпечатками `CLAUDE.md` или байтовые сравнения только на
  Windows — проверить, что шаг `core.autocrlf false` стоит до `checkout`.
- В журнале Windows у тестов только для Windows стоит ↓ — они пропускаются,
  искать, почему `process.platform` не `win32` или условие пропуска поменялось.
- Выпуск не публикуется, хотя тесты зелёные, — `publish` зависит от задания
  `test` по имени; переименование задания в `release.yml` рвёт эту связь.

## Что осознанно не тронуто

- Шаг публикации в `release.yml` — ни строки. actionlint отмечает в нём
  `npm version $VERSION` без кавычек (уровень «информация»), это было и раньше.
- Сами тесты. Два их недочёта, из-за которых нужны настройки выше, записаны
  отдельно: сравнение путей через `fs.realpathSync` вместо
  `fs.realpathSync.native` и ожидаемый отпечаток области `CLAUDE.md` без
  приведения концов строк (`_lf`), хотя установщик его приводит.
- `.gitattributes` не добавлен: он поменял бы концы строк во всех файлах, это
  отдельное решение.
- README: для пользователей ничего не меняется, раздела для участников в нём
  нет, а проверки в PR видны на самом PR.
