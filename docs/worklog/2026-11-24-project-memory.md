# Память проекта в .memory

bootstrap.py получил шаг `setup_project_memory` (вызывается один раз, сразу
после `setup_gitignore`): пишет `autoMemoryDirectory` в
`.claude/settings.local.json`, копирует старую память из
`<CLAUDE_CONFIG_DIR>/projects/<ключ>/memory`, добавляет `/.memory/` в
`.gitignore` для открытого репозитория или неизвестной видимости. Строка
`@.memory/MEMORY.md` — в управляемом блоке обоих шаблонов CLAUDE.md, её
обновляет обычный `update_claude_md`.

Почему так. Ключ папки (`claude_project_key`) сверен с настоящими папками в
`~/.claude/projects`: любой знак, кроме латинской буквы и цифры, становится
дефисом — двоеточие, слеш, подчёркивание, точка, `@`, кириллица. Старая память
копируется только тем запуском, который сам выставил настройку: потом
`.memory` и есть память, и повторное копирование положило бы устаревшего
двойника рядом с каждым файлом, который Claude успел обновить. Чужое значение
`autoMemoryDirectory` и нечитаемый `settings.local.json` не трогаются — шаг
сообщает и идёт дальше. Вопросов шаг не задаёт, поэтому `--all` проходит
без участия человека.

Что проверять первым при поломке: память не нашлась — сравнить вывод
`claude_project_key(путь)` с именем папки в `~/.claude/projects`; Claude Code
обрезает очень длинные пути (больше 200 знаков) и добавляет хеш — этот случай
не обработан. `.memory` попала в git открытого проекта — смотреть
`repo_visibility` (`gh repo view --json visibility`) и вывод шага.

Тесты: `tests/conftest.py` подменяет `CLAUDE_CONFIG_DIR` на пустую временную
папку и `repo_visibility` на «неизвестно» для каждого теста — ни один тест не
читает настоящий `~/.claude` и не зовёт `gh`.

Не тронуто: перенос памяти bd (uyf.6), общая память (uyf.2), удаление старой
папки — она остаётся как резерв.
