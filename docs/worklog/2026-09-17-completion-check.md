# 2026-09-17 — проверка отчёта о завершении, которая действительно останавливает

Хук `validate-completion.cjs` (событие SubagentStop) должен был возвращать к
работе субагента, который отчитался о завершении, не доделав. Замер по журналам
всех проектов на машине разработчика: около 790 срабатываний, 266 раз хук
«хотел остановить» — и ни одного раза не остановил. Две причины:

- `block()` в режиме `bypassPermissions` печатала предупреждение и выходила с
  кодом 0. У SubagentStop такой вывод до модели не доходит: он ложится в журнал
  субагента уже после его завершения. Ведущий не упомянул его ни разу.
- 165 из 266 тревог были ложными: путь к рабочей копии строился из
  идентификатора задачи, а в проектах с префиксом задача `bd_1c-oko-219` живёт в
  `.worktrees/bd-219`.

Остальное тоже было мёртвым: определение типа субагента искало в журнале поле
`parentToolUseID`, которого там нет, и инструмент `Task`, который теперь
называется `Agent`; ветки «supervisor/worker» остались от второй версии.

## Что сделано

Хук переписан маленьким. Отчёт берётся из поля `last_assistant_message`,
которое Claude Code передаёт в SubagentStop (проверено замером), — журнал
больше не разбирается. Отчётом считается сообщение с `BEAD <id> COMPLETE`;
всё остальное пропускается. Проверки по порядку, каждая останавливает с
причиной, в которой сказано, что сделать:

1. `Checklist:` есть, пунктов `- [ ]` нет.
2. Строка `Worktree:` есть; путь из неё (без обратных кавычек, кавычек и
   звёздочек, относительный — от корня проекта) указывает на каталог. Причина
   называет путь, по которому хук искал.
3. `git -C <рабочая копия> status --porcelain` пуст; в причине — сам вывод.
4. Если у рабочей копии есть origin: ветка из `rev-parse --abbrev-ref HEAD`
   есть в `ls-remote --heads origin` и указывает на тот же коммит, что HEAD.
   Если `ls-remote` сам упал (`execCommand` вернул `null`: нет сети, неверный
   адрес) — не останавливаем. Пустой ответ (`''`) — ветки нет, останавливаем.

`stop_hook_active: true` — пропускаем: субагента уже возвращали, спорить по
кругу незачем. Ранний выход по `hasBeads()` остался.

`block()` в `hook-utils.cjs` теперь останавливает в любом режиме. Её вызывает
только этот хук. `deny()` и `ask()` для PreToolUse не тронуты — там
предупреждение до модели доходит.

Тесты: `tests/hooks/validate-completion.test.js` — настоящие временные
репозитории, голый репозиторий в роли origin, git без глобальных настроек
машины (`GIT_CONFIG_GLOBAL` на пустой файл), чтобы подпись коммитов или чужие
перехватчики не влияли на результат. Тесты, которые ничего не меняют, делят
один проект: создание репозиториев занимает большую часть времени.

## Что проверять первым, если сломается

- **Хук снова никого не останавливает.** Приходит ли `last_assistant_message`:
  временно записать stdin хука в файл и запустить субагента. Если Claude Code
  переименует поле — хук молча пропускает всё.
- **Хук останавливает зря.** Причина в тексте называет путь или ветку — сверить
  с тем, что субагент написал в `Worktree:`. Путь в стиле Git Bash (`/m/repos/…`)
  на Windows разрешается неверно — это не поддержано.
- **Хук висит.** `ls-remote` ограничен 10 секундами (`execCommand`), запрос
  пароля в терминале выключен `GIT_TERMINAL_PROMPT=0`. Окно диспетчера учётных
  данных Windows эта переменная не отключает.
- **Субагент застрял в цикле.** Проверить, что `stop_hook_active` приходит как
  логическое `true`, а не строкой.

## Что осознанно не тронуто

- Подключение хука в Codex — отдельная задача.
- Маркеры отчёта `BEAD {BEAD_ID} COMPLETE` и `Checklist:` — их закрепляет
  `tests/test_bootstrap.py`.
- `bash-guard.cjs`, `session-start.cjs`.
- `approve()` по-прежнему печатает `{"decision":"approve"}`; работает, менять
  не просили.
- Отсоединённый HEAD останавливается отдельной причиной; других особых случаев
  для ветки нет.
