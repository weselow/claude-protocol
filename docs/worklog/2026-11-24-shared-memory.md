# 2026-11-24 — общая память: вопрос при установке и правило маршрута

Задача uyf.2 из эпика uyf (память). Впервые bootstrap пишет не в проект, а в
папку настроек Claude Code пользователя (`~/.claude` или `CLAUDE_CONFIG_DIR`).

## Что сделано

**Шаг «[shared memory]»** (`setup_shared_memory` и соседи в `bootstrap.py`,
раздел «Shared memory»). Вызывается из `main()` один раз — после успешного
`bootstrap_project`, а при `--all` — после всего пакета. В `bootstrap_project`
вызова нет нарочно: это настройка машины, а не проекта, и так шаг не
пересекается с параллельной задачей uyf.1, которая меняет `bootstrap_project`.

Четыре ответа — `existing <адрес>`, `new`, `local`, `never` — одинаково
приходят из вопроса (только когда у терминала человек и это не `--dry-run`)
и из флага `--shared-memory` (для плагина, CI, агента). Нет ни ответа, ни
флага, ни запомненного выбора — одна строка с флагом, больше ничего.

- `new` — `gh api user` за логином, `gh repo create <логин>/claude-memory
  --private`, `gh repo clone` в `<config>/shared-memory`, пустой `MEMORY.md`
  и README в одну строку, commit и push.
- `existing` — `git clone <адрес>`; если в клоне нет `MEMORY.md` или README,
  они создаются, но не коммитятся (чужой репозиторий — решать пользователю).
- `local` — папка с теми же двумя файлами, без git.
- `never` — запоминается, вопрос больше не задаётся. Флаг его отменяет.

Ответ хранится в `<config>/claude-protocol.json` под ключом `shared_memory`
(выбор, путь, удалённый репозиторий, язык) — раз на машину. Неудача (нет gh,
не вошёл, папка занята чужим) ничего не запоминает, печатает причину и
строку с флагом, код возврата 1.

**Блок в `<config>/CLAUDE.md`** — свои метки
`claude-protocol:shared-memory:begin/end`, текст из
`templates/shared-memory/CLAUDE-block{,-ru}.md` с путём вместо
`{{SHARED_MEMORY}}`. Путь под домашней папкой пишется как `~/…`, чтобы строка
работала и на другой машине. `marked_span` получил необязательную пару меток;
по умолчанию — прежние, поведение проектного CLAUDE.md не менялось. Перед
каждым изменением непустой файл копируется в
`<config>/claude-protocol-backups/<время>/CLAUDE.md`; одинаковый текст не
перезаписывается и копий не плодит. Начальная метка без конечной — файл не
трогаем, ошибка.

Язык блока: `--lang`, иначе запомненный, иначе язык проекта, иначе en. Язык
проекта не перебивает запомненный — иначе блок переключался бы при upgrade
каждого проекта на другом языке.

**Тесты** не трогают настоящий `~/.claude`: `tests/conftest.py` для каждого
теста ставит `CLAUDE_CONFIG_DIR` во временную папку (раньше тесты с
`bootstrap.main()` и `plugin_active_for` читали настоящую). gh и git
подменены `_FakeTools`.

## Что проверять первым при поломке

- Вопроса нет — `_stdin_is_a_person()` ложно (плагин, CI, перенаправленный
  ввод) или есть `claude-protocol.json` с `"choice": "never"`.
- Блок не обновляется — нет пары меток или в `claude-protocol.json` нет
  `path`.
- `new` падает — `gh auth status`; репозиторий с таким именем уже есть —
  тогда `--shared-memory existing <адрес>`.

## Что осознанно не тронуто

- Своё место для папки выбрать нельзя — только `<config>/shared-memory`.
- Правки внутри наших меток при обновлении не спрашиваются (в отличие от
  проектного CLAUDE.md с хешем в манифесте) — заменяются, прежний вариант
  лежит в резервной копии.
- Смена уже настроенного выбора флагом не делается: флаг пропускается с
  пояснением; чтобы перенастроить, удалить ключ из `claude-protocol.json`.
- Проектная память (`.memory`, `autoMemoryDirectory`) — задача uyf.1; хуки
  `git pull` при старте — uyf.3.
